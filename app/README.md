# Morpho アプリ

Markdown で書いた原稿から PowerPoint スライドを作る iPad アプリ。
現在 **0.15.0**（[変更履歴](CHANGELOG.md)）。
プロジェクト全体の紹介は [リポジトリのトップ](../README.md) にあります。

開発サーバでの実行・ビルド・検査など開発者向けの情報は
[`DEVELOPMENT.md`](DEVELOPMENT.md) へ。

## インストール

App Store 未公開のため、サイドロードで入れます。

**必要なもの**

- iPadOS 15.1 以降の iPad
- [AltStore](https://altstore.io/)（同一 Wi-Fi の PC で AltServer が必要）または
  [SideStore](https://sidestore.io/)（初回ペアリング後は iPad 単体で完結）
- サイドロード用の無料 Apple ID

**手順**

1. [Releases](https://github.com/c-colloid/Morpho/releases) から最新の
   `Morpho-x.y.z.ipa` をダウンロード（iPad の Safari でそのまま落とせます）
2. AltStore（＋ボタン → ipa を選択）か SideStore で開く
3. iPad の 設定 → 一般 → **VPNとデバイス管理** → 開発者を信頼

**補足**

- 初回起動時のみ、変換エンジン（pandoc.wasm・55.9 MB）の取得に
  ネット接続が必要です。以後の変換はすべて端末内で行われ、
  原稿が外部サーバーへ送られることはありません
- 無料 Apple ID の署名は7日で切れます。AltStore は AltServer と同一 Wi-Fi に
  いれば自動で再署名します（サイドロード枠は3アプリまで。AltStore 自身が1枠使用）
- Releases はアプリ本体の push のたびに自動でビルド・更新されます（約5分）。
  無いときは GitHub の **Actions タブ → Build IPA → Run workflow** で手動実行もできます

**アップデート**

新しい版が公開されると、アプリ起動時にバナーで知らせます。
入れ替えをワンタップにするには、AltStore / SideStore に Morpho の
「ソース」を一度登録しておきます:

1. AltStore: Browse → Sources → ＋ / SideStore: Sources → ＋ で次の URL を追加

   ```
   https://github.com/c-colloid/Morpho/releases/latest/download/source.json
   ```

2. 以後はストアの Update に新しい版が並び、タップで入れ替えられます
   （AltStore + 常駐 AltServer なら自動更新も効く）。アプリ内の文書は残ります

## 画面と操作

左が**原稿**、右が**プレビュー**。原稿を編集して手が止まると、
約 1.5 秒後に自動で変換されてプレビューが更新されます。
プレビューは変換結果の pptx（実際の出力そのもの）を解析して、
座標・配色・字サイズまで実寸で描画したものです。

| 操作 | 効果 |
|---|---|
| プレビュー右上のセグメント | プレビュー形式の切り替え（**スライド / 文書 / Web**）。文書は docx 出力のリーダー風表示（ページ組はしない）、Web は HTML 出力そのもの。どちらも発表者ノートは出ない。長押し等の編集操作はスライド形式のみ |
| スライドカードをタップ | 原稿のその区間の先頭へカーソルが移動 |
| 原稿ペインの「**段組み**」 | カーソル位置に列区切り（`+++`）を入れる。その行から右の列が始まる |
| 原稿ペインの「**出典**」 | カーソルのいるスライドの末尾に `/// ` を入れる。続けて出典を打つ |
| 段落を**長押し** | 改行位置の編集シート。「語 / 字」で粒度を切り替え、まとまりをタップした位置で改行。適用すると原稿に行末 `\` が入る |
| カード右上の「**装飾**」 | 装飾パネルを開く。プリセット（上下の帯・アクセント線・角丸カード・番号バッジ・基本図形 ▲◆⬡★➜）を置き、テーマ配色のスウォッチ・不透明度・枠線（太さ・色）・塗りなし・テキスト・位置サイズ（1% 刻み・長押しで連続変化）で整える。図形の形は後から切り替えられる。パネルを開いている間はスライド上の装飾を**直接ドラッグで移動・右下ハンドルでリサイズ**できる（0.5% スナップ）。行のマーク○を2つ以上付けて**グループ化**するとドラッグで一緒に動く。パネルはタイトルバーのドラッグで移動でき、「全スライドへコピー」で統一デザインにできる。装飾は Markdown には入らず文書ごとに保存され、pptx 書き出しに焼き込まれる。パネル下部の「文字サイズ」で**表紙タイトル・表紙サブタイトル・見出し・本文のサイズ（pt）**を文書ごとに変えられる（長い論文名などのあふれ対策。書き出しにも反映）。装飾は表紙にも置ける。デザイン一式は **.morphodesign**（JSON）として書き出し・読み込みできる |
| カード右上の「ノート追加 / ノート ▸ / 編集」 | 発表者ノートの確認と編集（原稿の `::: notes :::` に書き戻される） |
| ヘッダの「▶ 再生」 | 全画面スライドショー。横スワイプ / 左右端タップで送り、下部の「発表者」で発表者ビュー（ノート・次のスライド・経過時間） |
| ヘッダの「書類」 | 文書の一覧・新規作成・切り替え・削除・.md の読み込み・**その場で開く**（元ファイルを直接編集） |
| ヘッダの「書き出し」 | pptx / docx / md / Obsidian へ送る |

原稿は自動保存されます（手が止まって1秒後 + アプリを離れるとき即時）。
カーソル位置のスライドはプレビューで強調され、自動でスクロールします。

## 原稿の書き方

pandoc の Markdown が基本です。アプリが特別に扱うものだけ挙げます。

| 書き方 | 意味 |
|---|---|
| `# 見出し` | 新しいスライド（`##` 以下はスライド内の見出し） |
| `***` | 明示的なスライド区切り（**`---` は使わない**。front matter と衝突する） |
| 冒頭の `---` `title:` `---` | front matter。title があるとタイトルスライドが1枚できる |
| front matter の `footer: "…"` | **デッキ全体の出典・注釈**。スライドでは表紙を除く全枚の下端に小さく、docx ではページフッターとして全ページに、Web では本文末尾に 1 回出る。装飾パネルの「フッター」から入力欄で書ける（1 行で。`footer: \|` や配列は壊れるので診断が出る） |
| 行末の `\`（または スペース2つ） | その位置でスライド上の改行を固定。**日本語キーボードでは `¥` が入力されることがあり、`¥` では効かない**。`\` の入れ方: ソフトキーボードは `¥` を長押し、ハードウェアキーボードは **Option + `¥`**（実機で確認済み）。段落長押しの改行編集を使えば常に正しい `\` が入る |
| `- 項目` / `1. 項目` | 箇条書き / 番号付き |
| 半角スペース**2つ**（またはタブ）で字下げ | 箇条書きの入れ子。**半角1つでは入れ子にならず、全角スペースだと箇条書き自体が壊れる**（実測） |
| `::: notes` 〜 `:::` | 発表者ノート。スライドには出ず、pptx のノート欄に入る |
| `/// 出典: …` | **そのスライドの出典・注釈**（下端に小さく出る）。1 行・閉じ不要。全角の `／／／` も同じ（**間に空白の入った `/ / /` は記法にならない**）。原稿ペインの「出典」ボタンでも入る。同じスライドに複数書けば ` / ` で並ぶ。文言を空にすると、そのスライドだけデッキ全体の出典を出さない。docx では小さい段落、Web では `div.footer` になる。可搬形の `::: footer` 〜 `:::` も使える（`::: 出典` も可）。コメントではないので**観客に見える** |
| `+++` | **段組みの列区切り**。n 個で n+1 列。閉じ不要。全角の `＋＋＋` も、間に空白の入った `+ + +` も同じ。原稿ペインの「段組み」ボタンでも入る。見出しと末尾のノートは列の外に残る |
| `::: {.columns}` 〜 `::: {.column}` 〜 | pandoc 記法の段組み。従来どおり使えるが、**記号が全部半角**でないと無警告で 1 段になる。`+++` のほうが安全 |
| `![](名前.png)` | 画像。原稿ペインの「画像」ボタンで取り込むと自動で挿入される。ファイル名のみで参照する（パス・URL は不可） |
| `**太字**` `*斜体*` `` `コード` `` | 書式。和文の斜体は iOS の日本語書体に斜体字形が無いため傾かない |
| `{漢字\|かんじ}` | ルビ（でんでんマークダウン互換）。docx は本物のルビ、Web は `<ruby>`。pptx にはルビの仕組みが無いため 漢字（かんじ）になる |
| `《《ここ》》` | 傍点（圏点）。docx は本物の傍点、Web は text-emphasis。pptx は太字で近似 |

和文の一文を原稿内で複数行に折り返して書いても、半角スペースは混入しません。

## 書き出しと連携

| やりたいこと | 手段 |
|---|---|
| PowerPoint / Word で開くファイルを作る | 書き出し → pptx / docx → 共有シート →「"ファイル"に保存」（iCloud 含む。同名なら置き換え） |
| 原稿（.md）をバックアップ・共有する | 書き出し → md |
| Obsidian にノートとして送る | 書き出し →「Obsidian へ送る」（実験的。最後に開いた保管庫へ。本文約2万字まで） |
| Files / Obsidian 保管庫の .md を取り込む | 書類 →「読み込み」（アプリ内にコピーされる） |
| 元ファイルを**コピーせず**直接編集する | 書類 →「その場で開く」（0.8.0・実験的。保存は元ファイルへの上書き） |

「読み込み」はコピーなので、元ファイルは変わりません。元ファイルをそのまま編集したいときは
**「その場で開く」**を使います。Obsidian 側で編集した内容も、アプリへ戻ったとき・
文書を開き直したときに自動で取り込まれます（未保存の編集がある間は上書きしません）。

iOS の仕様でアプリを完全終了するとファイルへのアクセス権が切れますが、0.9.0 からは
保存してある bookmark で**自動的に繋ぎ直します**。失敗したときだけ書類一覧の「外部」バッジ →
「ファイルを選び直す」で再接続します（内容が食い違っていればどちらを使うか選べます）。
アプリ内には常にコピーが残るので、内容が失われることはありません。

## 既知の制約

- 表は**スライドプレビューでは枠と行数・列数だけ**が破線で描かれます（中身は次の版）。
  文書プレビューには中身まで描かれ、書き出した pptx / docx にも入ります
- プレビューの行の折り返し位置は、PowerPoint のフォントメトリクスと
  完全には一致しません
- **段組み**は 3 列以上書けますが、**スライドに出るのは 2 列まで**です
  （Web 書き出しでは 3 列とも出ます）。3 列以上のときは警告が出ます
- **列の先頭が画像や表で、その後ろに内容が続く**形は段組みにできません
  （pptx では後ろの内容が消えてしまうため）。この場合は 1 段のままにして理由を出します。
  画像を列の最後に置くか、`***` で別のスライドにしてください
- 文書（docx）プレビューはカーソル位置と連動しません（スライドプレビューのみ）
- 画像の大きさ・位置は自動で決まります。手で指定する手段はまだありません
