# 変更履歴

新しい版が上。バージョンは `app.json` の `version` で、画面上部のヘッダに出る
（実機で見ているものがどの版か分かるようにするため、push のたびに上げる）。

## 0.6.1 — 2026-08-28

装飾編集の UX 改善（実機フィードバック反映）。

- **操作ウィンドウを動かせるフローティングパネルに**: モーダルをやめ、
  タイトルバーのドラッグで好きな位置へ移動できる。プレビューを覆わないので、
  背面のスライドを見ながら微調整できる。位置は開き直しても保持
- **全スライドへ一括コピー**: パネル下部のボタンで、そのスライドの装飾を
  全スライドへコピー（他スライドの既存装飾は確認のうえ置き換え）
- **複製**（⧉。2% ずらして同じスライドに複製）と
  **重なり順の入れ替え**（↑↓。配列順 = 背面から前面。書き出しにも反映）
- **ステッパーの長押しで連続変化**（350ms 後から 90ms 間隔）。
  1% 刻みの位置調整が実用的な速さに
- パネルを開いたまま別カードの「装飾」を押すと対象スライドが切り替わる

## 0.6.0 — 2026-08-28（飾る力・その1）

装飾の最初の実装（`notes/roadmap-pptx.md` の三層分離の第3層）。

- **装飾プリセット**: スライドカードの「装飾」から、上の帯・下の帯・
  アクセント線・角丸カードを配置。色はテーマ配色（accent1〜6）連動で、
  テンプレートを差し替えても追従する
- **補助 UI**: テーマ配色のスウォッチ、不透明度（5% 刻み）、
  位置・サイズの微調整（スライド寸法の 1% 刻み）。生の座標や色コードは
  ユーザーに触らせない
- **プレビューと書き出しの一致**: プレビュー（カード・スライドショー）は
  実寸で装飾を描き、pptx 書き出し時は OOXML 後処理で spTree に
  `<p:sp>` を注入する（本文の背面・テーマ参照色のまま）
- 装飾は Markdown には書かず、文書ごとのデザインデータ
  （アプリ内 JSON）に保存。原稿の可搬性は変わらない
- 検査: プリセット・微調整・色解決（4件）と、実 pandoc pptx への
  注入・id 一意性・再パース無害性の統合検査（4件）
- 未実装（次以降）: ドラッグ移動・ハンドルでリサイズ、グループ化、
  番号バッジ、.morphodesign 書き出し

## 0.5.1 — 2026-08-28

アップデートの仕組み。

- **更新バナー**: 起動時に GitHub Releases の最新版と比較し、新しい版が
  あればヘッダ下にバナーで知らせる（オフライン・API 失敗は黙って無視）

- ipa の自動ビルドをアプリ本体の push で走らせるようトリガーを修正
  （0.4.2 / 0.5.0 のリリースが自動作成されなかった原因）

## 0.5.0 — 2026-08-28（刷り分けの土台）

プレビューを形式切り替えできる構造にした（設計は `notes/preview-formats.md`）。

- **Web プレビュー**: プレビュー右上のセグメントで「スライド / Web」を切り替え。
  Web は pandoc の HTML 出力（standalone・実際の出力そのもの）を
  可視 WebView にそのまま表示する。発表者ノートは CSS で非表示
  （クラスは残るので将来「付記」として見せる余地あり）
- **Converter 境界を形式対応に拡張**: `ConvertResult` を判別可能ユニオン
  （`kind: 'slides' | 'web'`）にし、`convert()` はオーバーロードで形式を受ける。
  既存のスライド型・呼び出しは無変更。変換はアクティブな形式だけ走らせる
  （ブリッジは単一 FIFO 直列・中断不可のため）
- **docx 書き出しから発表者ノートの漏洩を修正**（CLAUDE.md 落とし穴 8・新発見）:
  `::: notes :::` が docx では無警告のまま本文に混入していた。
  書き出し時に Lua フィルタで除去する（pptx は従来どおりノート欄へ）
- 検査を拡充: CSS 注入の単体検査、Web HTML と docx ノート除去の統合検査
- 文書（docx）プレビューは v0.7 以降（実出力調査済み: `scripts/dump-docx.mjs`）。
  飾る力は v0.6 に改番

## 0.4.2 — 2026-08-28

- **行末 `\` の改行がプレビューに反映されない不具合を修正**: pandoc は行内改行を
  `<a:br/>` で出力するが、プレビューのパーサが `<a:r>` しか読んでおらず
  落としていた（書き出した pptx には正しく入っていた）。出現順に拾って
  改行として描画する。統合検査に「端から端まで残る」検査を追加

## 0.4.1 — 2026-08-28

改行編集の刷新と、編集体験の修正。

- **改行位置の編集を刷新**: 内部表現を「改行を置く文字オフセットの集合」に変更
  （`locateEditable` / `rebuildBlock`）。対象を大幅に拡大し、普通の段落に加えて
  **箇条書きの1項目**（入れ子・継続行つきも）と手動改行 `\` が既に入った段落も
  編集できる。見出しと表だけ未対応（理由を表示）
- **語 / 字の粒度切り替え**: 語は Intl.Segmenter('ja') の単語分割
  （助詞は独立、約物は前に付く）、字はどこにでも改行を置ける手動調整用。
  切り替えても選択済みの改行位置は保持
- 箇条書きへ適用すると接頭辞ぶんの字下げが継続行に付き、リスト構造が壊れない
- **入れ子の箇条書きの書き方を明記**: 半角スペース2つ（またはタブ）で字下げ。
  半角1つでは入れ子にならず、全角スペースだと箇条書き自体が壊れる（実測）
- **プレビュータップで原稿へジャンプ**: スライドカードをタップすると
  原稿側のカーソルがそのスライドの先頭へ移動する
- **長文編集時のスクロール飛びを修正**: エディタを非制御化
  （native を真実に、プログラム的な差し替え時のみ remount）
- **字下げの実寸化**: プレビューの字下げをマスターの `marL` / `indent`
  （27pt 刻みのぶら下げ・実測）から計算。コードブロックの 27pt 字下げも再現
- 検査を拡充: check-linebreak を新 API 向けに書き直し（23件）、
  check-deck に字下げの検査を追加

## 0.4.0 — 2026-08-28（整える力）

プレビューから原稿へ書き戻す最初の編集機能。

- **ノート編集**: プレビューカードの「ノート追加 / 編集」から発表者ノートを
  その場で編集。確定は原稿の `::: notes :::` へ書き戻される（一方向フロー）。
  編集用 TextInput は本編集とは別インスタンスの UITextView で IME 安全
- **改行位置の編集**（初版）: 段落の長押し → 塊をタップで改行をトグル →
  適用で行末 `\` が入る。この版では普通の段落のみ対応
- スライド区切りの区間計算を純関数 `slideSegments` に共通化
- 安全策: pandoc のスライド数と原稿の区間数が食い違うとき
  （表の後ろのスライド分割など）はプレビューからの書き込みを拒否する
