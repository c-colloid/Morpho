# 変更履歴

新しい版が上。バージョンは `app.json` の `version` で、画面上部のヘッダに出る
（実機で見ているものがどの版か分かるようにするため、push のたびに上げる）。

## 0.16.5 — 2026-09-01

**発表者ノートの中に入れ子の div があると段組みが壊れる不具合を直した。**
`notes/footer-design.md` の多視点監査で見つかった既存の不具合 6・7 で、
フッターとは無関係に 0.15.0 の段組みで今日すでに踏める形だった。

- Quarto 系からのコピペで `::: notes` の中に `::: warning` などが入ると、
  ノートを列の外へ出す処理（閉じ柵から遡る方式）が内側の柵で止まり、
  ノートが最後の列の中へ包まれていた
- 同じ浅い追跡（`::: notes` で +1・任意の `:::` で -1）が入れ子の最初の閉じで
  ノートを終わらせていたため、ノートの中の `+++` が列区切りとして拾われ、
  **ノートの続き（観客に見せない情報）がスライド本体へ漏れていた**（実測）
- 柵の追跡を深さ管理にした。閉じ柵は直近の開き柵と対で、ノートが終わるのは
  深さが戻ったときだけ。規則の原本は `src/text/columns.ts` の `scanFences` で、
  ブリッジ側の写しと**本文が一致すること**を `check-columns.mjs` が常時検証する
  （片方だけ直すと検査が落ちる）
- ついでに: 末尾にノートが 2 つ並んでいれば両方を列の外に出す。段組みにしない
  とき（画像・表の後ろに内容がある形）に消す `+++` も、コードフェンスや
  ノートの中のものは触らなくなった
- 再現は `check-columns.mjs`（走査・展開）と `check-deck.mjs`（本物の pandoc で、
  枚数・レイアウト・本文が入れ子なし版と一致し、ノート本文が notesSlide 側に残ること）
  に固定した。`column-input.md` の検証結果の各ケースも退行検知として常時回す

**同じ族で、ノート欄の読み書きが原稿を壊す不具合も直した**（`src/preview/notesEdit.ts`）。

- ノートの範囲を「`::: notes` から最初のコロンだけの行まで」の遅延一致の正規表現で
  取っていたため、`::: notes` の中に `::: warning` 等があると内側の閉じで止まっていた。
  ノート欄で読むと続きが欠け、**書き戻すと続きと外側の閉じ柵が本文へ取り残されていた**（実測）
- 範囲は `src/text/columns.ts` の `scanFences`（深さ 0 で開いて閉じたブロック）で決める
  ようにし、判定規則を二重に持たなくした。開き柵の形（`::: {.notes}` / 引用の中）も
  段組みと同じ `NOTES_OPEN` に従う。閉じていないブロックは対象にしない
- CRLF 原稿は判定のときだけ `\r` を外して読む（ノート欄に `\r` を混ぜない）。
  書き戻しは 0.16.3 どおり原稿の改行コードを保つ
- 再現は `check-notes-edit.mjs` に固定した（入れ子 / 入れ子 + 2 ブロック並び / 属性形 /
  閉じていないブロック / ノートの中の `+++` / 繰り返し保存 / CRLF）

## 0.16.3 — 2026-09-01

- **デッキ全体のフッターが docx と Web にも出るようになった。** 0.16.0 では
  スライド（pptx）にしか載っておらず、docx / Web では**無言で消えていた**
  （設計の再監査で実測・`notes/footer-design.md` の「多視点監査と仕様の改訂」）。
  docx では**ページフッター**（Word の全ページ下端）、Web では本文末尾に 1 回出る。
  揃え・大きさはスライドと同じ設定を使う
- 文書プレビューは末尾に「ページフッター」として 1 回だけ見せる
  （フロー表示にページは無いので、毎ページ繰り返すのは嘘になる）
- スライドを一度もプレビューしていなくても docx / Web に出典が載る
  （帯の座標が要る pptx と違い、文言と揃えだけで決まるため）
- 検査は 28 件（docx の Open XML 妥当性 0 件と、子要素順を崩した較正が
  1 件以上鳴ることを含む）

- **ノート編集の書き戻しが原稿の改行コードを保つようにした**（0.16.2 で未修正としていた件）。
  CRLF 原稿では `::: notes` ブロックを `\r\n` で書き、ブロック直後の改行の畳み込みも
  `\r\n` を 1 つとして数える。複数行のノートは読むときに LF へ揃える（シートの表示用。
  原稿は触らない）
- ついでに直した既存の不具合: ノートを保存するたびにブロックの後ろに空行が 1 つ増えていた
  （LF 原稿でも。実測）。置き直すブロックが自分の改行を持つので、元の直後の改行を畳む
- 改行編集とノート編集の改行コード判定を `detectNewline`（原稿全体で見る）に共通化
- 検査に CRLF 3 件と「上書きを繰り返しても空行が増えない」を追加（`check-notes-edit`）

## 0.16.1 — 2026-09-01

  （カーソル → スライド対応）には触れない。カーソル位置のスライド推定
  （`***` 単独の境界が CRLF で消えていた）と段組みの列判定も、判定のときだけ
  `\r` を外す規約に揃えた（`src/text/lineEnding.ts`）
- 検査に CRLF の再現を追加（`check-columns` / `check-cursor` / `check-deck`。
  CRLF 原稿が LF 版と同じ pptx になることを本物の pandoc で確かめる）
- 未修正: 改行位置の編集（`lineBreakEdit.ts`）は CRLF 原稿で同じ理由で外れる
  （実測: `::: notes` の閉じ柵が読めず、ノートの後ろの段落が「見つからない」に
  なる。空行を挟まず段落の直後に置いた `+++` が段落へ溶ける）。ノート編集
  （`notesEdit.ts`）の読み取りは CRLF でも正しいが、書き戻しは LF で書くので
  改行コードが混在する（`lineBreakEdit` も同じ）。どちらも原稿への書き戻し
  経路なので、CRLF を保って書くかの判断とセットで直す

## 0.15.0 — 2026-08-31

**段組みが `+++` で書けるようになった。** 原稿ペインの「段組み」ボタン、
またはキーボードで `+++` と打つと、その行で列が分かれる。
設計と実測の根拠は [`../notes/column-input.md`](../notes/column-input.md)。

```markdown
# 三つの案

案A の説明

+++

案B の説明
```

- **`+++` は列区切り**。n 個で n+1 列になる。閉じも入れ子も要らない
- **全角の `＋＋＋` も、間に空白の入った `+ + +` も同じように効く**。
  日本語入力のまま打てるので、記号のために英字面へ切り替えなくてよい
  （従来の pandoc 記法は 8 行・半角記号 4 種で、日本語入力面のまま打てる文字が 0 だった）
- 見出しと末尾の発表者ノートは列の外に残る。**区間の本文はまるごと列に入る**ので、
  「段組みの前に導入の段落がある」だけでスライドが割れて編集機能が止まる、
  という従来の壊れ方が起きない
- コードフェンスの中と発表者ノートの中の `+++` は区切りにならない
- 従来の pandoc 記法（`::: {.columns}`）も**そのまま使える**

**言わずに失敗しないようにした**

pandoc は段組みの失敗にほとんど警告を出さない（62 通り試して 34 通りが失敗し、
うち 32 通りは完全に無警告）。そのため、次の 2 つは Morpho 自身が原稿を読んで伝える。

- **3 列以上**を書いたとき。スライドは 2 列までで 3 列目以降は出力されない
  （Web 書き出しでは 3 列とも出る）
- **列の先頭が画像や表で、その後ろに内容が続くとき**。この形は pptx では
  後ろの内容が消えてしまうため、**段組みにせず 1 段のまま**にして理由を出す。
  画像を列の最後に置くか、`***` で別のスライドにすると段組みにできる

**そのほか**

- 画像の挿入が、カーソルのいる列の中に入るようになった
- 段組みの区切り行を長押ししても原稿が壊れない
- 検査を 13 本 + tsc へ（`check-columns.mjs` を新設。記法の判定がアプリと
  変換器で食い違っていないことも常時検証する）

実機での確認はこれから。

## 0.14.0 — 2026-08-31

**壊れない土台。** 段組み（`::: {.columns}`）は pandoc が受け付けるので今までも
原稿に書けてしまい、書くと崩れ、編集すると原稿が壊れていた。その 6 件をまとめて直した。
設計と検証の記録は [`../notes/v014-foundation.md`](../notes/v014-foundation.md)。

**原稿が壊れなくなった**

- **カラムの中の段落を長押しして改行編集しても `:::` が消えない**。行種別に
  fenced div を足した。あわせて `::: notes` の中は改行編集の対象にしない
  （本文と同じ文がノートにもあると、本文を長押ししてノートが書き換わっていた）
- **改行位置がインライン記法の内側に落ちなくなった**。これは段組みと無関係に
  今までも踏めた経路で、画像・リンク・ルビ・傍点・強調が無警告で失われていた。
  とくに画像のパスの内側で改行すると、pandoc が出力を一切生成しなくなっていた
- **画像の挿入位置**を作り直した。行の途中には入れず、独立した段落として
  「カーソルのいるスライドの末尾」へ置く。フェンス行（`:::` / ```` ``` ````）を
  割らない。列の中にいるときはその列の中へ入る。
  全カーソル位置での健全率が 7/66 → 66/66 になった（枚数の一致と画像の残存で判定）

**プレビューの嘘が消えた**

- **段組みの左右で縦位置が揃う**。右の列だけ中央に寄っていたのは、プレースホルダの
  継承照合がレイアウトからマスターへ越境して**日付枠**を拾っていたため
- **Comparison（列に画像や表が混ざると選ばれる）で左右の見出しが重ならない**
- **表がプレビューから消えない**。表は `<p:graphicFrame>` で、図形の走査に
  掛かっていなかった。枠と行数・列数を破線で描く（セルの中身は次の版）
- **レイアウトごとの字サイズを読むようになった**。段組みの本文は実際には 21pt
  なのに 24pt で、画像＋本文スライドのタイトルは 15pt なのに 33pt で描いていた

**その他**

- **表や段組みがあっても装飾パネルが止まらない**。装飾は原稿に書かない層なので、
  「スライドと原稿の対応が取れません」の判定から外した。ノート編集・改行編集は
  従来どおり判定する。Alert の文面も、どのスライドが原因かを示すように書き直した
- 「全スライドへコピー」が、変換の途中や末尾に `***` を打った直後でも
  範囲外の装飾を消さなくなった
- 検査を 12 本 + tsc に増やし（`check-image-insert.mjs` を新設）、
  段組み・Comparison・表・レイアウト固有の字サイズを常時検証する
