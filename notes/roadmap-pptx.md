# MD → PowerPoint 高機能化ロードマップ（アイディア出し）

要望6項目（スライドショープレビュー / エレメント毎の見た目編集 / 改行位置の編集 /
図形・模様の装飾 / グループ / ノート確認)の設計検討。
競合6ツールの記法調査と iPad タッチ UI の操作設計は Sonnet パネルで実施し、
技術事実は pandoc.wasm 1.1.0 (Node) で実測した。

## 設計の背骨: 書き込み先は「pandoc が意味を持てるか」で決める

- 意味を持てるもの（強調・スタイル・改行・ノート）→ **Markdown 本体**へ書く
- 持てないもの（自由配置の図形・グループ・座標）→ **スライド直後の構造化コメント**
  `<!-- morpho: {...} -->` へ書く（Marp のディレクティブ方式 + reveal.js の
  「注釈は対象の直後」規約。.md 単体で持ち運べ、他のレンダラでは無害）
- プレビューは常に「確定済みの原稿」の再描画。プレビュー側に編集状態を持たない
- スライドの安定アンカーは pandoc ネイティブの見出し属性 `{#id}`

## 実測済みの事実（このロードマップの土台）

| 事実 | 検証 |
|---|---|
| `::: notes :::` → notesSlide1.xml に入り本文に漏れない | Node 実測 |
| 行末 `\` / スペース2つ → `<a:br/>` | Node 実測（2件） |
| `+east_asian_line_breaks` で和文折り返しのスペース混入が消える | Node 実測 |
| Lua フィルタは wasm で動く（ルビ変換まで確認） | Node + 実機 |
| 見た目のクラス指定は pandoc の bracketed span / header attributes がネイティブ | 記法調査 |

## フェーズ案

### v0.2.x 即効（数行の変更）
1. リーダーに `+east_asian_line_breaks` を足す（和文の行内折り返しが安全になる）
2. ノートのパース: notesSlideN.xml を読んでプレビューカードに折りたたみ表示
3. サンプル文書に `::: notes` と `\` 改行の使い方を載せる

### v0.3 見る力（読み取り専用・新記法なし）
- **実寸プレビュー**: reference-doc / pandoc 既定テンプレートの
  `<p:sldSz>` `<a:off>` `<a:ext>` `theme1.xml` を読んで、プレースホルダの
  位置・サイズ・配色どおりに 16:9 のカードを描画（CLAUDE.md 既定路線）
- **スライドショー**: 全画面・横スワイプ・左右端タップ送り（Keynote 語彙）。
  ピンチインで編集へ復帰
- **発表者ビュー**: 現在/次スライド + ノート + 経過時間のボトムシート
- 依存: react-native-svg（Expo Go 同梱）

### v0.4 整える力（Markdown への書き戻し）
- **改行編集モード**: プレビューの段落を長押し → 文節境界に薄い縦線 →
  タップで `\` 改行を挿入/解除。エディタの TextInput には触れない
  （IME 安全）。文節分割は Intl.Segmenter('ja') を想定 — **Hermes での
  対応状況は未検証**。なければ助詞ベースのヒューリスティックに落とす
- **ノート編集**: ノートパネルをタップで軽量 TextInput 化 → `::: notes` へ書き戻し
- **インスペクタ v1**: 要素タップ → theme1.xml 由来のスウォッチ提示 →
  `[テキスト]{.accent}` のような**意味クラス**を挿入。生の色値は原稿に書かない。
  クラス → rPr の解決は Lua フィルタ（実装可能なことは検証済み）

### v0.5 飾る力（構造化コメント + OOXML 後処理）
- **装飾プリセット**: 帯・アクセント線・角丸カード・番号バッジ等を「＋」から配置。
  テーマ配色連動。ドラッグ移動・ハンドルでリサイズ
- **グループ**: 複数選択 → グループ化 → 一括移動（Figma 語彙）。
  データはメンバー ID の配列
- 実現: 書き出し時に pandoc が吐いた pptx を WebView 内で開き（fflate は導入済み）、
  spTree に `<p:sp>` / `<p:grpSp>` を注入する **OOXML 後処理**。
  レイアウト名の書き換え（配線盤）と同じ技術で、pandoc を差し替えずに済む

### その先
- 装飾のデータモデルは EMU 座標・テーマ参照色で持ち、**自前 writer（MIT）に
  差し替えても生き残る形**にする。v0.5 の後処理が事実上 writer の前身になる
- CLAUDE.md の結論どおり: エディタが主役、変換器は交換可能

## リスクと未検証
- Intl.Segmenter の Hermes 対応（改行編集モードの文節境界）
- 実寸描画のフォントメトリクス差（PowerPoint の折り返しと完全一致はしない。
  「実際の出力そのもの」を読む方針は維持しつつ、行の折り返しは近似と明記する）
- pandoc 既定テンプレートのレイアウト座標が reference-doc なしでどう入るか
- 構造化コメントは stripHtmlComments の Lua フィルタで除去される設計と衝突しない
  （morpho: プレフィックスだけ除去対象から外す）
