# MD → PowerPoint 高機能化ロードマップ（アイディア出し）

要望6項目（スライドショープレビュー / エレメント毎の見た目編集 / 改行位置の編集 /
図形・模様の装飾 / グループ / ノート確認)の設計検討。
競合6ツールの記法調査と iPad タッチ UI の操作設計は Sonnet パネルで実施し、
技術事実は pandoc.wasm 1.1.0 (Node) で実測した。

## 設計の背骨: 三層分離（2026-08-27 更新）

当初は「装飾も .md 内の構造化コメントに書く」案だったが、
**「MD は内容・可搬性・Git のためのもの。デザインはアプリ内のみでもよい」**
という方針判断により、CSS-HTML 型の分離に改めた。

```
content.md          内容。可搬・Git 管理・他アプリへ流用
テーマ（スタイル定義）  クラス・スライド規則・装飾プリセットが各出力形式で
                    何を意味するか。文書間で再利用。共有・Git 可能なファイル
文書デザインデータ     一回性の図形・個別上書き・グループ。アプリ内 DB が既定。
                    .morphodesign (JSON) として書き出し可能（Git 再現用・任意）
```

- **テーマは出力形式ごとにコンパイルする**: pptx は reference-doc + Lua +
  OOXML 注入、docx は reference.docx + custom-style、epub/Web は本物の CSS。
  「一つの原稿から刷り分ける」が「一つのテーマから刷り分ける」に拡張される
- 内容に属するもの（ノート・改行・ルビ・強調・意味クラス）は従来どおり
  **Markdown 本体**。日本語記法は独自発明ではなく青空文庫式
  （｜親文字《ルビ》等）を採用する — 劣化しても日本語の書き手には読める、
  既に確立した「日本語圏の MFM」だから
- 装飾の多くはインスタンスでなく**セレクタ**（「タイトルスライドに帯」
  「h1 下にアクセント線」）に付くので、テーマ側の規則で吸収できる。
  アンカーが要る一回性の図形は少数に留まる見込み
- プレビューは常に「確定済み状態」の再描画。プレビュー側に編集状態を持たない

### アンカー（一回性の図形をどのスライドに結ぶか）

- **案A（既定）**: 見出しに `{#s-xxxx}` を自動付与。pandoc ネイティブ属性で
  出力には現れない。堅牢。.md にわずかな痕跡
- **案B（設定）**: 見出しテキストのハッシュ照合。.md は無垢だが、
  見出し変更で装飾が迷子になる（再リンク UI が必要）

## 実測済みの事実（このロードマップの土台）

| 事実 | 検証 |
|---|---|
| `::: notes :::` → notesSlide1.xml に入り本文に漏れない | Node 実測 |
| 行末 `\` / スペース2つ → `<a:br/>` | Node 実測（2件） |
| `+east_asian_line_breaks` で和文折り返しのスペース混入が消える | Node 実測 |
| Lua フィルタは wasm で動く（ルビ変換まで確認） | Node + 実機 |
| 見た目のクラス指定は pandoc の bracketed span / header attributes がネイティブ | 記法調査 |

## フェーズ案

### v0.2.x 即効（数行の変更）
1. リーダーに `+east_asian_line_breaks` を足す（和文の行内折り返しが安全になる）
2. ノートのパース: notesSlideN.xml を読んでプレビューカードに折りたたみ表示
3. サンプル文書に `::: notes` と `\` 改行の使い方を載せる

### v0.3 見る力（読み取り専用・新記法なし）
- **実寸プレビュー**: reference-doc / pandoc 既定テンプレートの
  `<p:sldSz>` `<a:off>` `<a:ext>` `theme1.xml` を読んで、プレースホルダの
  位置・サイズ・配色どおりに 16:9 のカードを描画（CLAUDE.md 既定路線）
- **スライドショー**: 全画面・横スワイプ・左右端タップ送り（Keynote 語彙）。
  ピンチインで編集へ復帰
- **発表者ビュー**: 現在/次スライド + ノート + 経過時間のボトムシート
- 依存: react-native-svg（Expo Go 同梱）

### v0.4 整える力（Markdown への書き戻し）
- **改行編集モード**: プレビューの段落を長押し → 文節境界に薄い縦線 →
  タップで `\` 改行を挿入/解除。エディタの TextInput には触れない
  （IME 安全）。文節分割は Intl.Segmenter('ja') を想定 — **Hermes での
  対応状況は未検証**。なければ助詞ベースのヒューリスティックに落とす
- **ノート編集**: ノートパネルをタップで軽量 TextInput 化 → `::: notes` へ書き戻し
- **インスペクタ v1**: 要素タップ → theme1.xml 由来のスウォッチ提示 →
  `[テキスト]{.accent}` のような**意味クラス**を挿入。生の色値は原稿に書かない。
  クラス → rPr の解決は Lua フィルタ（実装可能なことは検証済み）

### v0.6 飾る力（v0.5 から改番。v0.5 はプレビューの形式切り替え土台に充てた）（テーマ + アプリ内デザインデータ + OOXML 後処理）
- **装飾プリセット**: 帯・アクセント線・角丸カード・番号バッジ等を「＋」から配置。
  テーマ配色連動。ドラッグ移動・ハンドルでリサイズ
- **グループ**: 複数選択 → グループ化 → 一括移動（Figma 語彙）。
  データはメンバー ID の配列
- 実現: 書き出し時に pandoc が吐いた pptx を WebView 内で開き（fflate は導入済み）、
  spTree に `<p:sp>` / `<p:grpSp>` を注入する **OOXML 後処理**。
  レイアウト名の書き換え（配線盤）と同じ技術で、pandoc を差し替えずに済む

### v0.14 以降（2026-08-31 追記）

0.6〜0.13 で「飾る力」と刷り分けの土台が入ったので、次は**第2層（テーマ）**へ進む。
版割りと受け入れ条件は `status-and-plan.md`、段組み・画像配置の設計は
`columns-and-images.md` にある。要点だけ:

- **v0.14** はパーサの土台直し。段組みは今日すでに原稿に書けてしまい、
  書くと崩れる／原稿が壊れる経路が 6 件ある（`status-and-plan.md` の A-1〜A-6）
- **v0.16 のテーマ層はこのロードマップの第2層そのもの**で、段組みの付属物ではない。
  意味クラス挿入（インスペクタ v1）・縦書き・docx/epub の資材はすべてここへ集まるので、
  スキーマを列比だけで設計しないこと
- **アンカー（案A / 案B）の決着は v0.18**（画像の自由配置）で必要になる。
  それまでは決めなくてよい

### その先
- 装飾のデータモデルは EMU 座標・テーマ参照色で持ち、**自前 writer（MIT）に
  差し替えても生き残る形**にする。v0.6 の後処理が事実上 writer の前身になる
- CLAUDE.md の結論どおり: エディタが主役、変換器は交換可能

## 検討メモ: 装飾の編集専用画面（2026-08-28・実機フィードバック）

カード上の直接操作はスクロールとの同居が本質的に窮屈。v0.6.3 で
「ドラッグ中はスクロール無効化」を入れたが、根本解としては
**全画面の装飾編集モード**（スライドショーの stage + DecorEditLayer の
組み合わせで実装可能。スクロール競合が構造的に消え、キャンバスも大きい）が
候補。判断は 0.6.3 のスクロールロックを実機で使ってから:
それで十分ならカード上編集を維持（コンテキストを失わない利点がある）、
まだ窮屈なら v0.7 で編集専用画面を作る。

**2026-08-31 追記:** 0.7〜0.13 では作らず、カード上編集のまま来た。
`columns-and-images.md` は画像配置の入口として**全画面の配置モード**（v0.18）を置く方針で、
ここで積み残した判断はそこで決着する。ただし `SlideShow` の stage は
横ページングの `ScrollView` と幅 22% の左右タップゾーンを含むので、
「スクロール競合が消える」のは縦方向だけ — 配置モード中は横ページングと端タップを止める必要がある。
なお実機での使用感（大きな装飾を置いた状態で縦スクロールと長押しができるか）は**まだ未検証**で、
`status-and-plan.md` の実機周回の受け入れ条件に入れてある。

## リスクと未検証
- Intl.Segmenter の Hermes 対応（改行編集モードの文節境界）
- 実寸描画のフォントメトリクス差（PowerPoint の折り返しと完全一致はしない。
  「実際の出力そのもの」を読む方針は維持しつつ、行の折り返しは近似と明記する）
- pandoc 既定テンプレートのレイアウト座標が reference-doc なしでどう入るか
- テーマ形式は CSS 風の語彙（color / font-size / background）の YAML とし、
  完全な CSS を装わない。epub/Web 出力時のみ本物の CSS に変換する
