# 現在地（0.13.0）と残りの計画

いま何が動いていて、何が残っているか。棚卸しの結果を一枚にまとめる。
機能の設計は `roadmap-pptx.md`（三層分離）・`columns-and-images.md`（段組みと画像配置）・
`column-input.md`（段組みの入力）、
技術事実は `../CLAUDE.md`、検証の経緯は `findings.md` にある。

このファイルの技術事実は pandoc-wasm 1.1.0（= **pandoc 3.10**）を Node から回した実測。
**実機 iPad・PowerPoint・Word での見え方は別物**で、そこは「実機未検証」と明記する。

## 未消化の課題

### A. コードから判明した不具合（段組みを書くと今日から露出する）

段組み（`::: {.columns}`）は**すでに原稿に書ける**。pandoc が受け付けるからで、
アプリ側は何も止めていない。書いた瞬間に次が起きる。

**設計と検証は済んだ → `v014-foundation.md`。** 6 件すべてを実ハーネスで再現し、
修正を当てて直ることと既存が壊れないことを確認した（`npm run check` 相当が緑）。
その過程で分かった追加の事実を先に書いておく:

- **A-1 は段組み専用ではない。** `Content with Caption`（本文 → 画像）の本文枠も
  `<p:ph idx="2">` なので同じ経路でマスターの日付枠を拾う。画像を使えば段組みなしでも出る。
  `fixtures/pptx-benchmark.md` も現状で既に発症している
- **改行編集はインライン記法の内側でも原稿を壊す**（段組みと無関係に今日も踏める）。
  画像・リンク・ルビ・傍点・強調が無警告で失われ、画像のパスの内側で改行すると
  **pandoc が出力を一切生成しなくなる**（落とし穴 3 の致命クラス）
- **A-6 を単独で出すと後退する。** A-1/A-2 と同じ照合器に乗るので、
  先に出すと行頭記号とぶら下げを失う。同じ版に入れる

| # | 症状 | 原因 | 影響 |
|---|---|---|---|
| A-1 | 右の列だけ文字が縦中央に寄る | `findInherited` の idx 照合がレイアウトからマスターへ越境し、**マスターの日付枠**（`idx="2" type="dt" anchor="ctr"`）を拾う | 高 |
| A-2 | Comparison で左右の見出しが重なる | 同関数が type を idx より先に見るため、`type="body"` が 2 つあるレイアウトで先頭勝ちになる | 高 |
| A-3 | カラム内の段落を長押しして改行編集を確定すると、`:::` フェンスが本文に溶けて段組みが消える | `locateEditable` の行種別に fenced div が無く、`:::` 行を段落の一部として飲み込む | 高（**原稿を壊す**） |
| A-4 | 画像挿入がフェンス行の途中に入ると、`::: {.col` / `![](x.png)` / `umns}` に割れる | 画像挿入は `patchBody` を通らず、カーソル位置へ直接 splice する | 高（**原稿を壊す**） |
| A-5 | 表が入った列が丸ごと空白になる | 表は `<p:graphicFrame>`。`parseShapes` は `<p:sp>` しか走査しない | 中 |
| A-6 | 段組みの本文が 14% 大きく、画像＋本文スライドのタイトルが 2.2 倍で描かれる | レイアウト固有の `lstStyle` を読まず、`DeckInfo` がデッキ全体で 1 組しか持たない | 中 |

A-1 / A-2 / A-6 の根拠（pandoc 既定テンプレートの実測値）:

```
slideMaster1  title=ctr / body idx1=(anchor なし) / dt idx2 sz=half anchor=ctr / ftr idx3 / sldNum idx4
Two Content   body idx1 x=457200 cx=4038600 (anchor なし) / body idx2 x=4648200 cx=4038600 (anchor なし)
Comparison    body idx1 x=457200 anchor=b / idx2 x=457200 / body idx3 x=4645026 anchor=b / idx4 x=4645026
lstStyle lvl1  master title=3300 body=2400 ／ Two Content=2100 ／ Comparison=1800
               ／ Content with Caption title=1500 body#2=1050 ／ Section Header title=3000
```

A-1〜A-6 はすべてコードと OOXML の突き合わせで確定していて、**実機で確認する必要はない**
（プレビューの描画結果が変わるだけで、原因は決定的）。ただし A-3 / A-4 は原稿を壊す経路なので、
段組みを README で案内する前に必ず塞ぐ。

### B. 実機未検証の積み残し

| 項目 | 何が未確認か |

### D. 判断待ち

- **GPL と App Store**。判断が要るのは配布の瞬間だけなので、実装は止めない。
  ただしテーマ層で reference-doc（.pptx / .docx）を組み込みで持つと、
  リポジトリの MIT に触れる。**組み込みテーマはテーマファイルのみ**という線を守れば先送りできる
- **`{#s-xxxx}` を原稿に書くか**（一回性の配置をどの見出しに結ぶか。roadmap-pptx.md の案A/案B）。
  画像配置の実装時に決まる

## v0.14 の前に置く実機周回

**0.10.0〜0.13.0 の 4 版が未検証のまま積まれている。** そして v0.14 以降の成果は
どれも「見た目が合っているか」であり、実機でしか正否が出ない。先に 1 周入れる。

受け入れ条件（全部が緑である必要はない。1・2 が赤なら v0.14 の前に潰す）:

1. 完全終了 → 再起動 → 外部ファイルの編集が降りてくる。失敗しても内容が失われず、
   手動の再接続 UI に落ちるだけであること（0.9.0）
2. 大きめの装飾（角丸カード 92%×72%）を置いた状態で装飾パネルを開き、
   カード上で縦スクロールと本文長押しができる（0.6.3 の判断の答え合わせ）
3. スライドショーで画面端から横スワイプしてページが送れる（幅 22% のタップゾーンが上に載っている）
4. スライドショー再生中に iPad を回転して、見ているページが保たれる
5. テンプレートを入れた文書で、装飾・文字サイズ・配線盤が同時に効く（0.11.0）
6. 画像を数枚含む文書で連続編集したときのヒープ（0.13.0。115 MB の見積もりは画像なしの値）
7. ルビ・傍点・画像を含む原稿を pptx / docx / Web の 3 形式で書き出し、
   PowerPoint / Word / ブラウザで開けること（0.12.0・0.13.0）

## 残りの計画

段組みと画像配置の設計は `columns-and-images.md`。版割りはそちらと同じものを再掲する。

| 版 | 中身 | 実機に届くもの |
|---|---|---|
| **周回** | 上記の実機周回。出た不具合を patch で潰す | 4 版ぶんの手当て |
| **v0.14** 原稿を守る | A-3（fenced div の行種別 + インライン記法の内側で改行させない）/ A-4（画像挿入の `patchBody` 統一）/ ガードの層分け。設計と検証は `v014-foundation.md` | カラム内で長押ししても、画像を入れても原稿が壊れない。表を 1 つ入れただけで装飾が止まらなくなる |
| **v0.14.1** プレビューの嘘を消す | A-1 / A-2（継承照合）/ A-5（表の枠）/ A-6（レイアウト固有の `lstStyle`）。**A-6 は A-1/A-2 と不可分** | 左右の縦位置が揃い、Comparison で見出しが重ならず、表のある列が空白にならず、字サイズの嘘が消える |
| **v0.15** 段組みの入力 | **`+++`（列区切り）の記法・展開・正規化・診断・挿入 UI**。設計は `column-input.md`。pandoc ネイティブ記法も引き続き受け付ける | 記法を覚えずに段組みが書ける。打ち間違いが沈黙しない |
| **v0.16** テーマ層 | 第2層の本体。意味クラスのコンパイラ・列比・組み込みテーマ 1 本。縦書きとインスペクタ v1 の席もここ | 段組みの列比が変えられる。見た目が変わる |
| **v0.17** 刷り分け | docx / epub・Web への段組みの落とし方、書き出し前の劣化告知、`headingSegments`、PDF 可否の実験 | 「この配置は Word では 1 本の流れになります」が出る |
| **v0.18** 画像配置 | 画像の当たり判定、`Placement`、`<p:pic>` の xfrm 上書き、全画面の配置モード | 画像の大きさ・位置をタッチで決められる |
| **v0.19** テーマの共有 | テーマの編集 UI・書き出し・読み込み。文字サイズと配線盤の移設 | テーマを文書間で使い回せる |

この順の理由は 3 つ。

- **v0.14 が先**なのは、段組みが今日すでに書けてしまうから。壊れる経路を残したまま
  UI で誘導すると、被害が増えるだけになる
- **v0.16 のテーマ層は段組みの付属物ではない**。roadmap-pptx.md の第2層そのもので、
  意味クラス挿入（インスペクタ v1）・縦書き・docx/epub の資材はすべてここへ集まる。
  スキーマを列比だけで設計しないこと
- **v0.18 が最後**なのは、画像の自由配置がライブプレビューの hot path に
  初めて OOXML 後処理を持ち込むから。遅延の実測（B）が前提になる

### 版に紐づかない宿題

- pandoc.wasm の同梱とライセンス判断。**wasm の取得経路の永続キャッシュ**（オフライン起動）は
  同梱すれば同時に解決するので、判断を先に片付ける価値がある
- `fixtures/pptx-benchmark.md` は書き換えない。基準値が動く
