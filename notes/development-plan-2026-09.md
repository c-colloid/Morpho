## 2. レポートの提言への採否

| レポートの提言 | 採否 | 理由 |
|---|---|---|
| 実機検証の一斉消化を最優先 | **採用** | 自分でも `status-and-plan.md` で「v0.16 の前に 1 周入れる」と決めていた。9 版ぶん積んだ今はなおさら |
| README の版表記を直し、再発を仕組みで防ぐ | **採用** | 版は `app.json` の 1 箇所が正。README は版番号を書かず変更履歴へのリンクだけにする（機械同期より「書かない」が確実） |
| CI で `check` を回しているか未確認（推測） | **確認済み: 回していない** → **採用（追加する）** | ipa ビルドは macOS runner で 60 分かかるが、`check` は Node だけで数分。PR と push で回す別ジョブにする |
| 案A: カーソル単位の部分変換 | **保留（計測が先）** | CLAUDE.md の判断は「文書長が効いてきてから足す」。50 枚 47 ms の実測に対し、まだ誰も長文書で困っていない。先に**端から端の遅延**（後処理・展開・解析・描画込み）を測り、文書長との関係を数字で持ってから決める |
| 案B: bridgeHtml の正規表現パーサを DOMParser に置換 | **見送り** | レポート自身も様子見を推奨。回帰リスクが 20 件の落とし穴対処すべてに及ぶ。ただし bridgeHtml を**テンプレートリテラルから分離して型検査が効く形にする**ことは別件として採用（下記 3-C） |
| 案C: EditorScreen からプレビュー同期を切り出す | **部分採用** | 全面リファクタリングはしない。テーマ層で触る範囲（変換トリガー・カーソル対応・装飾オーバーレイ）だけを hook に出す |
| テーマ層（第2層）の着手 | **採用（版番号を振り直す）** | v0.16 は使ってしまったので **v0.19** に |
| PDF の 1 回の実験 | **採用（前倒し）** | 半日で済み、結果次第で README の「PDF / epub 書き出し」の書き方が変わる |
| 変換器は pandoc.wasm 継続、自作は先送り | **採用（現状維持）** | CLAUDE.md の結論と同じ |
| 「pandoc では実現不可能な組版要件」の一覧化 | **採用（テーマ層の設計に含める）** | 縦書き・ルビの精密制御など。自作 writer への切り替えトリガーをここで持つ |
| pandoc.wasm 同梱の技術検証を先行 | **採用（オフライン起動の確認とセット）** | ライセンス判断は配布の瞬間まで先送りのまま |
| 落とし穴カタログの線形増加が保守コスト（推測） | **一部同意** | 件数は増えるが、各項目は「検出 → 診断」の 1 行で済んでいる。作り込みすぎない方針（CLAUDE.md）を維持し、lint を製品機能にしない |

## 3. 直近 2〜4 週間の作業

順番に意味がある。**1 と 2 が終わるまで新機能は積まない。**

### 3-A. 即日（コードに触らない）

- [x] `README.md` の版表記を直す（版番号を消して変更履歴へのリンクにする）
- [x] `status-and-plan.md` の冒頭に「版割りはこのファイルが正」の一行を足す（本計画と同時）

### 3-B. CI に `check` ジョブを足す（半日）— **済（0.18.1）**。設計と検証は `foundation-2026-09.md` A

- `build-ipa.yml` とは別のワークフロー `check.yml`。`ubuntu-latest`・Node 22・`npm ci && npm run check`
- トリガーは `pull_request` と `push`（`app/**` の変更時）。ipa ビルドと違って main 以外でも走らせる
- 検査スクリプトが pandoc.wasm を CDN から取っているなら、runner のネットワークで通るかを最初に確認する。
  通らなければ wasm を actions/cache に載せる（55.9 MB。キャッシュ上限内）
- 受け入れ: PR を開いたら数分で緑赤が付く。`fixtures/pptx-benchmark.md` は触らない

### 3-C. 実機周回（1〜2 週間。patch は 0.18.x）

`status-and-plan.md` の受け入れ条件 1〜9 と「0.18.0 の確認」1〜5 を **順序を変えて**回す。
0.18.0 の TextInput の変更が壊れていると、それより前の検証の結果が信用できないため。

1. **0.18.0 の確認 1・2・5**（ソフトキーボードとツールバー・物理キーボードのバー・スクロールで focus しない）
2. **0.18.0 の確認 4**（画像・段組み・出典・ノート・改行編集の書き戻しでキャレットが飛ばない）—
   remount 廃止の答え合わせ。ここが赤なら他に進まない
3. 受け入れ条件 **9**（0.15.0 `+++`・全角 `＋＋＋`・3 列警告・列頭画像の診断）と **8**（0.14.0 段組みの縦位置・列内の表）
4. 受け入れ条件 **7**（ルビ・傍点・画像を pptx / docx / Web で書き出し、PowerPoint / Word / ブラウザで開く）—
   0.17.x のフッターと Content with Caption のタイトルもこの周で PowerPoint で見る
5. 受け入れ条件 **1・2・5**（bookmark 自動再接続・装飾パネルとスクロール・テンプレート）
6. 受け入れ条件 **3・4** と 0.18.0 の確認 3（スライドショーの端スワイプ・回転・Slide Over）

出た不具合は 0.18.1, 0.18.2, … の patch で潰す。過去の実績（機能 1 つに patch 2〜4 本）から、
**9 版ぶんで 10〜20 本の patch を見込む。** 2 週間で消えなければ、残りは
「実機で見た症状」を `status-and-plan.md` B に書き足して v0.19 と並走させる。

### 3-D. 計測（3-C と並走。各半日）— PDF は **済（出せない。`foundation-2026-09.md` D）**。残り 3 件は実機

`status-and-plan.md` B の「測っていないもの」を数字にする。結論は CLAUDE.md の実測値表へ追記する。

| 計測 | 目的 | 決まること |
|---|---|---|
| 端から端の遅延（入力停止 → 画が出るまで。後処理・展開・解析・描画込み）を 10 / 50 / 150 枚で | 部分変換（案A）の要否 | 150 枚で 300 ms を超えるなら v0.20 で部分変換。超えないなら見送り継続 |
| 画像を数枚含む文書で連続編集したときのヒープ | 115 MB は画像なしの値 | 画像の総量に上限を設けるか |
| 機内モードで起動 | README の「初回のみネット接続が必要」が本当か | 同梱（WKURLSchemeHandler）の優先度 |
| `to: 'pdf'` を pandoc.wasm に投げる | PDF が原理的に可能か | README の「PDF / epub」の表現。不可なら「pdf は pptx / docx を Files 経由で」と書き換える |

### 3-E. テーマ層に向けた足場 — **済（0.18.1）**。この環境で進められたので 3-C を待たずに出した。
実機での確認は 3-C の周回に含める（`foundation-2026-09.md` C）

- `EditorScreen.tsx` からプレビュー同期（変換トリガー・カーソル ⇔ スライド・装飾オーバーレイの座標）を
  `usePreviewSync` 系の hook に出す。**動作を変えない**（`npm run check` が緑のまま）
- `bridgeHtml.ts` の中身を `app/src/converter/bridge/*.js` の実ファイルに分け、ビルド時に文字列へ束ねる
  （テンプレートリテラルの「`` ` `` と `${` を使うな」制約を外し、tsc / lint を効かせる）。
  DOMParser への置換はしない。文字列の出し方を変えるだけ
- 「pandoc では実現できない組版要件」の一覧を `theme-layer.md`（新規）に書く。
  縦書き・ルビの位置制御・傍点の種類・禁則・段組みの列比。各項目に「テーマ層で吸収できるか / writer の差し替えが要るか」を付ける

## 5. 版に紐づかない宿題

- **pandoc.wasm の同梱とライセンス判断。** 3-D のオフライン計測で「機内モードで起動できない」と出たら、
  同梱の技術検証（WKURLSchemeHandler・`fetchWasm()` の差し替え）だけ先に進める。
  App Store に出す判断はそのときまで先送りのままでよい（CLAUDE.md）
- **ドキュメントの版ずれの再発防止。** README に版番号を書かない。`status-and-plan.md` は
  棚卸しのたびに冒頭の版を更新し、版割りの表は本ファイルへ寄せる
- `fixtures/pptx-benchmark.md` は書き換えない
